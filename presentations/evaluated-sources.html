About this document

How to Read This Supplement

The technical overview makes claims about the state of the field, validated strengths, and gaps. This supplement provides the sources behind those claims so readers can evaluate them independently.

Between February and May 2026, we conducted a structured pressure-test of the Living Memory and Alexandria architecture against 35+ external sources spanning academic papers, open-source projects, industry articles, and commercial products. Each source was evaluated in a dedicated document that compares its approach to ours, identifies what we should adopt, and notes where our design diverges.

Not all original source materials are preserved (some were live demos, videos, or paywalled content). Where external links exist, they are included below so you can evaluate each source directly.

The May 2026 update adds three categories the earlier supplement omitted: (a) Sentra's Company Brain series, which crystallized substrate-vs-lens vocabulary; (b) internal architectural decision records (ADRs) and planning documents that drive the current architecture; (c) prior-art from Andrew's tenure at Macmillan Learning (UXF, ASO26 / IA-EA, EDR Decision Support), where the substrate-lens pattern shipped in production before Alexandria existed.

Academic & research papers

Papers and Surveys

MAPLE: Memory, Learning, Personalization Framework Paper
Deepak Babu Piskala — ALA 2026 @ AAMAS 2026
Introduced the M/L/P decomposition we adopted for our architecture. Context rot taxonomy (poisoning, distraction, confusion, clash). Validated hierarchical token-level memory and event-triggered learning. Source of our conflict resolution gap identification.
GitHub arXiv:2602.13581
Contributed: M/L/P architecture, context rot taxonomy, event-triggered learning design
Memory in the Age of Agents (Survey) Paper
Hu et al. — NUS, Fudan, Renmin, Peking, Oxford, Georgia Tech
Comprehensive 2026 survey establishing the Forms-Functions-Dynamics taxonomy for agent memory. Places 3D hierarchical token-level memory at the apex. Validates session lifecycle, forgetting-as-architecture, and episodic memory as a structural gap across the field.
Paper list (GitHub)
Contributed: Taxonomy placement, episodic memory gap validation, offline consolidation cycle
ALMA: Learning to Continually Learn via Meta-learning Agentic Memory Designs Paper
zksha
Meta-learns memory designs as executable code. Reflect-generate-verify and examine-before-commit patterns. AlfWorld/TextWorld benchmarks. Validated our approach to memory as active architecture, not passive storage.
GitHub
Contributed: Reflect-generate-verify pattern, examine-before-commit discipline
Everything is Context: Agentic File System Paper
Xu et al. — CSIRO Data61, ArcBlock, U Tasmania, UNSW
File-system abstraction for context engineering. Introduced Constructor/Updater/Evaluator vocabulary. Validated the concept of context manifest (what was selected, excluded, and why).
AIGNE framework (GitHub)
Contributed: "Context Evaluator" as named architectural role, context manifest concept
Cornelius: Agentic Note-Taking (24 Articles) Article series
Cornelius (@molt_cornelius)
24-article series on knowledge management. Article 24 ("What Search Cannot Find") crystallized the graph-vs-search distinction: search retrieves what you ask for; graph traversal discovers what you didn't know to ask. Foundation for our knowledge graph architecture.
Contributed: Graph-vs-search framing, metabolism metaphor, Alexandria naming inspiration
World Models, AGI & Life–Mind Continuity Paper
Safron et al., Phil. Trans. R. Soc. A 384:20240533 (2026); contributors incl. Levin, Krakauer, Mitchell, Gershman, Tenenbaum
Editorial introduction to a Royal Society themed issue (18 contributions) on world models in natural and artificial intelligence; read as a gateway, not a single paper. Its useful contribution is a vocabulary for distinguishing kinds of world models (causal vs. self-referential, individual goal-directed vs. collective, narrative vs. mechanistic), which sharpens the loosely-used "context, frame, lens, substrate, world model" terms in our architecture. Source bias flagged up front: curated by the active-inference / Free Energy Principle community, with the scaling hypothesis represented mostly as a foil.
Royal Society (rsta)
Contributed: vocabulary for distinguishing world-model types; gateway to 18 contributed papers for on-demand depth
Open-source projects

Open-Source Implementations

Letta / MemGPT Open source
UC Berkeley; letta-ai
OS-inspired virtual context management. MemFS (Context Repositories) with git-backed memory. Scores 74% on LoCoMo with filesystem-only approach. Critical benchmark: proved that for simple retrieval, the mechanism doesn't matter. Our graph's value must come from discovery, reasoning, and evolution.
GitHub arXiv:2310.08560
Contributed: Benchmarking gap identification, filesystem-vs-graph strategic framing
Cognee Open source
topoteretes
Hybrid RAG knowledge engine with knowledge graph construction from unstructured data. Memify (spaced repetition, decay) for memory strengthening. Identified our gap: we have forgetting but not the inverse (demand-driven increase of retrieval probability).
GitHub
Contributed: Memory strengthening gap, knowledge quality evaluation layer concept
Engram Open source
Terronex-dev
TypeScript neural memory format with decay tiers, quality metadata, and HNSW indexing. Hierarchical temporal multi-modal memory. Closest to our decay architecture. Validated our approach; we adopted their DecayConfig concept.
GitHub npm
Contributed: Decay tiers design, time decay in retrieval, quality block pattern
MIE (Memory Intelligence Engine) Open source
Kraklabs
Go-based memory graph with five typed nodes (Facts, Decisions, Entities, Events, Topics). MCP server. CozoDB backend. Agent-as-Evaluator pattern. Confirmed our propositional framing advantage: MIE stores flat text; we store claims with reasoning chains.
GitHub
Contributed: Confirmed propositional framing differentiation, Agent-as-Evaluator pattern
CIE (Code Intelligence Engine) Open source
Kraklabs
Code intelligence engine with CozoDB backend, Tree-sitter parsing, 20+ MCP tools. Operational complement to MIE. Architecture reference for how code-specific knowledge could integrate with a general knowledge graph.
GitHub
Contributed: Architecture reference for code-specific knowledge integration
memU Open source
NevaMind-AI
24/7 proactive memory framework with two-bot architecture. Scores 92% on LoCoMo. Memory-as-filesystem metaphor. Demonstrated that proactive memory (suggesting relevant context unprompted) is valuable and feasible.
GitHub Website
Contributed: Proactive memory concept, LoCoMo benchmark reference
ATHF (Agentic Threat Hunting Framework) Open source
Nebulock-Inc
LOCK pattern for agent trust boundaries. MITRE ATT&CK coverage mapping. Domain-specific application of our agentic memory pattern in cybersecurity. Validated the need for trust boundaries on procedural memory (skills).
GitHub PyPI Blog
Contributed: LOCK pattern for trust boundaries, skill signature verification concept
QMD v2 Open source
tobi
Optional P-layer retrieval with vault search and SDK. Evaluated as potential retrieval component. Decision: keep boundary with getContext; QMD operates at a different layer.
GitHub
Contributed: Confirmed getContext retrieval boundary is correct

Harness engineering & thought leadership (April 2026)

Harness Engineering, Evals & Thought Leadership

Sources added in April 2026, covering harness engineering (how to govern and evaluate agentic systems), context engineering, and the thought leaders whose work directly shaped our architecture.

NLAH: Natural-Language Agent Harnesses Paper
Pan et al. — Tsinghua University, arXiv:2603.25723 (2026)
First controlled experimental evidence for agent harness design. Decomposes any harness into six components (Contracts, Roles, Stage Structure, Adapters, State Semantics, Failure Taxonomy). Critical finding: more structure can hurt — verification modules reduced performance when acceptance criteria diverged from evaluators. File-backed state was the #1 most valuable module. Validates our scratchpad/session-log architecture with experimental data.
arXiv:2603.25723
Contributed: Six-component harness decomposition, verifier alignment requirement, evidence that file-backed state is the most valuable harness module
Thoughtworks: Harness Engineering for AI-Assisted Delivery Industry
Thoughtworks Technology Radar
Framed harness engineering into three pillars: context engineering, architectural constraints, and "garbage collection" against entropy. Identified that agents replicate whatever patterns already exist in the repository — including suboptimal ones. Without active entropy fighting, code quality compounds downward.
Contributed: Three-pillar harness framework, entropy resistance as a first-class concern, garbage collection pattern
OpenAI: Harness Engineering with Codex Industry
OpenAI Engineering
AGENTS.md as ~100-line table of contents, not a manual. Rigid dependency direction enforcement via custom linters. "Doc-gardening" agents that scan for stale documentation. 20% Friday cleanup time didn't scale; automated entropy processes did. Key insight: "Context is a scarce resource. A giant instruction file crowds out the task."
Contributed: AGENTS.md architecture, mechanical validation, doc-gardening automation, entropy scan process
Anthropic: Demystifying Evals for AI Agents Industry
Anthropic
Complete eval stack: tasks, trials, graders (code/model/human), transcripts, suites. Distinction between capability evals (hill-climbing, start at low pass rate) and regression evals (guardrails, near 100%). Swiss Cheese Model from safety engineering: no single eval layer catches everything; multiple methods combined fill the gaps.
Documentation
Contributed: Capability vs regression eval distinction, pass@k/pass^k metrics, Swiss Cheese Model for agent quality
HumanLayer: Context-Efficient Agent Engineering Industry
HumanLayer (N7 & N8)
Two articles. N7: suppress passing test output (replace 200 lines of "PASS" with one checkmark), --bail in agent test runs, deterministic backpressure. N8: "Frequent Intentional Compaction" with 40-60% context utilization target. Research → Plan → Implement workflow. Subagents are about context control, not role-playing. "A bad line of plan leads to hundreds of bad lines of code."
Contributed: run_silent pattern, context budget zones, Research→Plan→Implement workflow, subagent context isolation
Andrej Karpathy: Software 2.0, LLM OS Thought Leadership
Andrej Karpathy — Stanford, Tesla, OpenAI
"Software 2.0" framing: neural networks as the new programming paradigm, where the model IS the program and the training data IS the source code. The "LLM OS" vision: LLMs as the kernel of a new computing stack, with tools, memory, and file systems as peripherals. This directly shaped our architecture: the knowledge graph is the "file system" of the LLM OS, and agents are processes managed by the kernel.
Contributed: Software 2.0 paradigm, LLM OS metaphor for architecture, kernel/peripheral framing for agent systems
Boris Cherny: Context Engineering as a Discipline Thought Leadership
Boris Cherny — Stripe, Shopify
Reframing "prompt engineering" as "context engineering" — the systems-level discipline of designing what information flows to a model and when. The key insight: the context window is the new bottleneck, not the model capability. Our architecture directly addresses this through token-budgeted getContext, berrypicking retrieval, and the living wiki as a pre-compiled context source.
Contributed: Context engineering framing, token budget as architectural constraint, pre-compiled context concept
Program-Aided Language Models (PAL) Paper
Gao et al. — CMU, 2023
LLMs generate structured programs (code) as intermediate reasoning steps rather than free-form text. The code is then executed to produce the answer. This pattern directly influenced our approach: agents produce structured artifacts (scratchpads, session summaries, decision traces), not just chat responses. Code-as-reasoning, not prose-as-reasoning.
arXiv:2211.10435
Contributed: Structured artifact generation, code-as-reasoning pattern, separation of reasoning from execution
2026 substrate vocabulary

Sentra Company Brain Series

The 2026 source most directly shaping current architecture. A multi-part series by Ashwin Gopinath (Sentra) crystallizing the three-layer memory model (factual / interaction / action) and the substrate-vs-lens vocabulary. Read in the May 2026 review session; produced the current substrate-lens-frame architecture as the synthesis output.

Company Brain Series Thought Leadership
Ashwin Gopinath — Sentra (founder)
Three-layer memory model: factual (what happened), interaction (why, what was meant, what was debated), action (procedural / trigger / execution / outcome). Substrate-vs-lens vocabulary: substrate generalizes; ontologies on top of it do not. Doing nothing as a first-class action. Validated the architectural posture we were already building toward; named primitives we had implicitly. Local amendment: non-action only counts when intentional, decisive, and persisted with rationale. Local addition: frame as the missing transient task-binding layer Sentra and others don't ship.
Contributed: substrate / lens vocabulary, factual / interaction / action three-layer model, intentional non-action framing. Synthesis output: substrate-lens strategy + implementation plan, May 2026.

Prior art (Macmillan)

Substrate-Lens Pattern in Production

Substrate-vs-lens is not a new architectural bet. The same pattern shipped in production at Macmillan Learning under three different names. These are prior-art sources for the architecture documented in the technical overview.

UXF — Customer Experience Contextualization Framework Prior art
Andrew Crenshaw — Macmillan Learning
Customer-experience substrate with role-shaped lenses. Two-tier identity (Profile + Context) maps directly to lens-vs-frame: Profile is the persistent consumer-keyed contract; Context is the transient task-binding. Validated the substrate-lens pattern years before Sentra named it.
Contributed: substrate-lens pattern proof in production; Profile/Context maps to Lens/Frame
ASO26 / IA-EA — Adoption Details Prior art
Andrew Crenshaw — Macmillan Learning
Per-course persistent record (course + institution + time) as substrate. SFDC decision-trace objects with as-is vs as-was fields as state-change primitive in microcosm — exactly the typed event consolidation the current substrate ships in Alexandria. Sales / support / leadership dashboards as role-conditioned lenses over the same memory. The credibility artifact for substrate-lens-frame at production scale.
Contributed: state-change as first-class primitive (proven), bounded entity timeline, role-conditioned lens proof
EDR > Decision Support Prior art
Andrew Crenshaw — Macmillan Learning
Role-conditioned decision-support surfaces (CEO vs sales vs support) over a shared memory layer. Validated that lenses don't compound restriction — wearing more lenses widens scope. The pattern that Alexandria's multi-lens UNION rule formalizes.
Contributed: role-conditioned-surface proof; multi-lens scope semantics

Methodology

How We Evaluated

Each source was evaluated using a consistent approach:

1. Understand the source on its own terms: what problem does it solve, for whom, with what trade-offs?

2. Map to our architecture: where does it overlap, where does it diverge, where does it address a gap we have?

3. Identify adoptable patterns: what should we take from this source? What's the minimal useful adoption?

4. Pressure-test our assumptions: does this source invalidate or weaken any of our architectural bets?

5. Document honestly: where the source is ahead of us, say so. Where we're ahead, explain why with evidence.

Limitations

This is not a formal systematic review. Sources were selected based on relevance, availability, and discovery during active research, not from a comprehensive literature search. Some sources were evaluated from blog posts or README files, not from peer-reviewed publications. The evaluation was conducted by a small team and reflects our architectural perspective. We encourage readers to evaluate the original sources independently and draw their own conclusions.
